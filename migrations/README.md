# Database migrations

Alembic is the authoritative upgrade mechanism for existing databases.

## Rules

1. ORM models inherit from `app.database.base.BaseModel`.
2. Alembic reads the same `Base.metadata` and Pydantic settings as the app.
3. Never store database passwords in `alembic.ini`.
4. Review every autogenerated revision before applying it.
5. PostgreSQL enum value additions require an explicit migration review;
   Alembic may not detect enum-label changes automatically.
6. Existing legacy `.sql` migration files are historical records and must not
   be silently deleted.
7. Never run `Base.metadata.create_all()` as an upgrade mechanism for an
   existing database after Alembic adoption.

## Normal workflow

```powershell
python -m alembic current
python -m alembic heads
python -m alembic check
python -m alembic revision --autogenerate -m "describe change"
python -m alembic upgrade head
```

For a brand-new database, the migration chain should be able to build the
schema from an empty PostgreSQL database.
